# AI 주제 추천 리스트 뷰 설계

## 상세 모달 확장

- 후보 표에는 카테고리, 주제, 추천 이유, 상태만 표시하고 각 셀은 한 줄 말줄임표 처리한다.
- 후보 행을 클릭하거나 키보드 Enter/Space로 선택하면 후보 전용 상세 모달을 연다.
- 상세 모달은 전체 주제, 카테고리, 추천 이유, 출처 링크, 상태와 오류 메시지를 표시한다.
- 상세 모달의 작업 영역은 후보 상태에 맞춰 `이 주제로 글 생성`, `글 보기`, `삭제`를 표시한다.
- `GENERATING` 후보는 모달에서도 생성과 삭제를 비활성화한다.
- 기존 게시글 미리보기 모달과 후보 모달은 별도 DOM 요소와 닫기 동작을 사용한다.

## 목표

AI 주제 추천 후보를 카드 모음 대신 비교하기 쉬운 리스트형 표로 표시하고, 각 후보를 개별 삭제할 수 있게 한다.

## 범위

- 기존 `#topic-candidate-list` 영역을 표 컨테이너로 렌더링한다.
- 한 후보를 한 행으로 표시한다. 열은 카테고리, 주제, 추천 이유, 출처, 상태, 작업이다.
- `NEW`와 `FAILED` 후보에는 글 생성 버튼을, `GENERATING` 후보에는 비활성 상태 버튼을, 생성 완료 후보에는 글 보기 버튼을 유지한다.
- 모든 후보 행에 삭제 버튼을 둔다. 삭제는 `topic_candidates` 행만 삭제하며, 이미 연결된 `Article`, `PublishJob`, `Job`은 삭제하지 않는다.
- 좁은 화면에서는 표 컨테이너가 가로 스크롤되어 텍스트와 작업 버튼이 잘리지 않는다.

## API

- `DELETE /api/topic-candidates/{candidate_id}`를 추가한다.
- 존재하지 않는 후보는 `404`를 반환한다.
- 삭제 성공은 `{ "success": true }`를 반환한다.
- 생성 중(`GENERATING`) 후보도 삭제 버튼으로 즉시 제거하지 않고 `409`를 반환해 생성 선점 상태를 보존한다.

## UI 동작

- 삭제 버튼 클릭 시 해당 후보의 주제가 포함된 확인 대화상자를 표시한다.
- 사용자가 확인하면 삭제 API를 호출하고, 성공 시 목록과 통계를 다시 조회한다.
- 실패 시 기존 후보 목록은 그대로 두고 오류 메시지를 표시한다.
- 표의 출처는 기존과 같이 안전한 외부 URL만 링크로 표시한다.

## 검증

- API 테스트로 새 후보와 생성 완료 후보 삭제가 후보 목록에서만 사라지는지 확인한다.
- 생성 중 후보 삭제가 `409`인지 확인한다.
- JavaScript 문법 검사를 실행하고, 전체 Python 테스트를 실행한다.
